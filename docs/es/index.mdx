# Qyro Runtime

Qyro Runtime es la capa que una aplicación gráfica Python utiliza **mientras se está ejecutando**. Centraliza el arranque del toolkit, la configuración, los recursos, la información del entorno, la telemetría y un ciclo de vida reutilizable para componentes de interfaz.

<Warning>Qyro está en estado alpha. Las APIs y el comportamiento pueden cambiar entre versiones. El flujo de escritorio es el foco actual; móvil todavía no se considera estable.</Warning>

## Qué incluye

| Área | Responsabilidad |
| --- | --- |
| Contexto | `ApplicationContext`, metadatos, plataforma, modo de ejecución, título, icono e instancia nativa de la aplicación. |
| Configuración | Carga de `base.json`, override por plataforma y secretos. |
| Recursos | Resolución de archivos por sistema operativo, modo source/frozen y bundles protegidos. |
| Interfaz | Adaptadores para PySide6, PyQt6, PySide2, PyQt5, Kivy, Tkinter y modo headless. |
| Componentes | Mixin/decorador `Component`, props, estilos y hooks de montaje y resize. |
| Observabilidad | Hook de excepciones para consola o Sentry. |
| Seguridad en reposo | Lectura de recursos protegidos y secretos autenticados generados por Qyro CLI. |

## Qué no incluye

Qyro Runtime no crea proyectos, no compila, no firma y no publica aplicaciones. Esas tareas corresponden a [Qyro CLI](https://github.com/Neuri-AI/qyro-cli):

- scaffolding e inicialización de proyectos;
- build y bundle;
- instaladores, firma y notarización;
- automatización de releases y distribución.

Tampoco incluye APIs de bridge web de ejemplos antiguos de PPG.

## Flujo de arranque

Al crear el primer `ApplicationContext`, Qyro realiza este flujo:

1. Descubre la raíz, plataforma y modo de ejecución.
2. Busca y combina la configuración.
3. Elige el adaptador de telemetría.
4. Selecciona el framework solicitado, configurado o autodetectado.
5. Verifica que el framework esté disponible.
6. Instala el hook de excepciones.
7. construye `AppMetadata` y la aplicación nativa.
8. Comparte el mismo contenedor con los contextos creados después.

```text
ApplicationContext
       │
       ▼
 EngineContainer ──► entorno ──► plataforma / source / frozen
       ├───────────► settings ─► AppMetadata
       ├───────────► resources ► rutas absolutas
       ├───────────► telemetry ► sys.excepthook / Sentry
       └───────────► framework ► QApplication / Tk / Kivy / headless
```

## API de entrada

La mayoría de aplicaciones solo necesita estos símbolos:

```python
from qyro import ApplicationContext, Component, get_resource
```

- Usa `ApplicationContext` en la ventana o aplicación principal.
- Usa `Component` en widgets reutilizables.
- Usa `get_resource()` cuando necesitas resolver un recurso fuera de una clase.

Consulta [Instalación](/es/installation) y [Inicio rápido](/es/quickstart) para crear la primera aplicación.

## Estado y compatibilidad

El manifiesto acepta Python `>=3.10,<3.16`. Cada binding tiene además su propio rango; revisa [Frameworks](/es/frameworks) antes de elegir una combinación. La distribución declarada por el proyecto se llama `qyro-engine`, mientras que el paquete importable es `qyro`.

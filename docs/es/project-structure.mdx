# Estructura de un proyecto

Qyro CLI crea el proyecto inicial mediante `qyro init`. La plantilla elegida proporciona código, dependencias y configuración; a partir de ahí desarrollas dentro de esa estructura.

Para los datos de la aplicación hay dos carpetas principales: **`settings/` para configuración** y **`resources/` para archivos de entrada**.

```text
mi-app/
├── pyproject.toml
├── main.py                 # o el entry_point de la plantilla
├── settings/
│   ├── base.json
│   ├── windows.json         # opcional
│   ├── mac.json             # opcional
│   ├── linux.json           # opcional
│   ├── release.json         # perfil para entregas
│   └── secrets.json         # local, cuando corresponda
├── resources/
│   ├── base/
│   ├── windows/             # opcional
│   ├── mac/                 # opcional
│   └── linux/               # opcional
├── views/                  # organización que puede añadir la plantilla
└── components/             # organización que puede añadir la plantilla
```

El árbol muestra la organización habitual; las plantillas pueden añadir módulos y assets propios. Las carpetas opcionales se utilizan cuando tu aplicación necesita diferencias por plataforma.

## Código y dependencias

`pyproject.toml` describe el proyecto y sus dependencias. El archivo indicado por `entry_point` en settings inicia la aplicación. Los módulos adicionales contienen vistas, componentes y lógica propia: organízalos según las necesidades del proyecto generado.

El CLI utiliza estos datos para ejecutar y construir la aplicación. No tienes que trasladar su configuración al código cada vez que llamas a `qyro start`.

## `settings/`: configuración

`base.json` contiene los valores comunes: nombre, versión, autor, binding y entry point, además de opciones que tu aplicación necesite leer.

Los JSON de plataforma permiten definir diferencias para Windows, macOS o Linux. `release.json` contiene opciones del tooling para preparar entregas. `secrets.json` es local y no debe contener credenciales que versiones públicamente. La combinación y el tratamiento de secretos se explican en [Settings](/es/settings) y [Secrets](/es/secrets).

## `resources/`: archivos de la aplicación

Guarda aquí textos, imágenes, fuentes, estilos, plantillas y otros assets. `resources/base/` contiene los archivos comunes; las carpetas de plataforma contienen variantes cuando las necesites.

Tu código consulta esos archivos mediante el Engine. El CLI los incorpora al build según su configuración. Así mantienes un nombre de recurso en el código mientras su ubicación física cambia al empaquetar. La guía [Resources](/es/resources) desarrolla su uso.

## Artefactos generados

Al construir y preparar entregas aparecen `build/`, `release/` y `.qyro/`. Son resultados del tooling, separados del código y los datos de entrada. Si necesitas opciones de build adicionales, el CLI puede leer `build.json` en la raíz.

Versiona código, configuración pública y assets; excluye secretos y artefactos generados en el `.gitignore` de tu proyecto. Guarda preferencias o documentos del usuario en una ubicación escribible apropiada, separada de los recursos de instalación.

Continúa con [Build, bundle y distribución](/es/tooling) para completar el recorrido del CLI.

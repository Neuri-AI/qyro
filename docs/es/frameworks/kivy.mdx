# Qyro con Kivy

Kivy proporciona `App`, widgets, propiedades y su propio loop. Qyro puede aportar configuración y recursos sin intervenir en la construcción del árbol. Instala el extra `kivy` del Engine en tu entorno.

```python
from pathlib import Path
from kivy.app import App
from kivy.uix.label import Label
from qyro import ApplicationContext


class MainApp(App):
    def __init__(self, context, **kwargs):
        super().__init__(**kwargs)
        self.context = context
        self.title = context.get_default_window_title()

    def build(self):
        return Label(text=f"Qyro: {self.context.execution_mode.value}")


if __name__ == "__main__":
    context = ApplicationContext(
        framework="kivy", custom_root=Path.cwd().resolve(), enable_sentry=False
    )
    MainApp(context).run()
```

En un proyecto generado con `qyro init` y `--binding Kivy`, coloca el código en el script indicado por `entry_point` y ejecuta `qyro start` desde la raíz del proyecto. `App.run()` ejecuta la aplicación que has creado. `KivyAdapter.create_application()` solo intenta recuperar `App.get_running_app`; antes de crear una app puede devolver `None`. Llamar al `run()` del contexto sin que el adaptador conozca tu app puede crear una `GenericKivyApp` sin tu interfaz. Por eso este ejemplo llama al método nativo.

## Construir una sola vez

`Component` invoca `render()` durante su montaje e ignora su retorno. El patrón antiguo `App, Component, ApplicationContext` con `build(): return self.render()` puede construir el árbol dos veces. En una `App` de Kivy usa `build()` una vez, como arriba; para hooks de inicio/cierre usa `on_start` y `on_stop`. No se necesita `Component` para cargar settings y resources.

QSS y `resizeEvent` no son mecanismos Kivy. Usa propiedades, `bind`, KV, canvas y `Clock` cuando corresponda. El título/icono pueden asignarse como atributos de la app. `context.app` no se actualiza automáticamente como registro dinámico de la app propia.

## Recursos y build

El ejemplo `docs/es/example-apps/kivy_app.py` añade un texto de recurso y contador. Lee [Aplicaciones completas](/es/examples). El CLI aporta hidden imports Kivy y recopila KV en patrones de raíz, `views` y `components`; no todas las opciones del dataclass `KivyConfig` están conectadas a los hooks utilizados por el contenedor.

Se revisó y ejecutó el ejemplo de construcción y eventos en el entorno local. Un import exitoso no garantiza un proveedor gráfico/OpenGL utilizable. La existencia del adaptador Kivy tampoco implica build móvil conectado: consulta [Compatibilidad](/es/compatibility).
